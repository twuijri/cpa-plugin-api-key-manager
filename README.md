# مفتاح · Miftah

إضافة مستقلة لإدارة المفاتيح الافتراضية داخل CLIProxyAPI، بكود جديد وليس فرعًا من Credit Manager.

**الحالة: 0.1.0-alpha.3 — نسخة أولى قابلة للاختبار، وليست إصدارًا إنتاجيًا مكتملًا.**

## الموجود فعليًا

- إضافة Linux أصلية بواجهة CPA ABI 1 / RPC schema 4، وليست لوحة شكلية فقط.
- إبقاء مفاتيح CPA الأصلية خارج سياسات الإضافة دون تعديلها.
- توليد مفاتيح `mf_` عشوائية، حفظ SHA-256 فقط، إظهار النص مرة واحدة.
- إنشاء وتعديل وتدوير وتعطيل المفاتيح؛ مالك، انتهاء صلاحية، وقائمة موديلات مباشرة ومسارات اختيارية مسموحة.
- اختيار الموديلات بأسمائها الأصلية من بيانات حسابات البروكسي، أو إدخال الاسم الحقيقي يدويًا إذا لم يظهر. لا يلزم إنشاء اسم مسار للموديل المباشر.
- إعداد سعر تقديري للموديلات الجديدة أثناء إنشاء المفتاح، ثم تعديل سعر وبدائل كل موديل من صفحة الموديلات المباشرة. حفظ إعدادات الموديلات الجديدة والمفتاح عملية واحدة دون تعديل السياسات الموجودة.
- ميزانيات إجمالية ويومية وأسبوعية وشهرية، حد RPM وحد التزامن.
- حجز تقديري قبل التنفيذ، ثم تسوية من usage إن توفرت؛ سجل للحجوزات غير المحسومة.
- مسارات بأسماء بديلة و1–5 أهداف، ترتيب بالسحب والإفلات أو لوحة المفاتيح.
- Fallback قبل بدء البث فقط، لأكواد محددة أو لأخطاء غير مصنفة باختيار صريح.
- طلبات نصية غير متدفقة ومتدفقة عبر host.model callbacks، دون إعادة إرسال المفتاح الافتراضي للمزوّد.
- واجهة عربية متجاوبة، إحصائيات وسجل تغييرات وتصدير الاستخدام.
- لا CDN أو خطوط أو مكتبات خارجية في واجهة التشغيل. مفتاح الإدارة في ذاكرة الصفحة فقط.
- إدارة محمية بمفتاح إدارة CPA؛ الموارد العامة تحتوي ملفات واجهة ثابتة فقط.

## قيود يجب معرفتها قبل الاستخدام

1. **لا تثبّتها على السيرفر الأساسي بعد.** اختبار التكامل تم مع CPA v7.2.146 ومزوّد محلي وهمي، وليس مع حساباتك أو كل المزوّدين.
2. تم اختبار OpenAI chat/completions، بما فيه streaming. توجد محولات أولية لـ Responses وClaude لكن تحتاج اختبارات تكامل مستقلة قبل اعتمادها. لا دعم للصور/الصوت/الفيديو/WebSocket أو أدوات البحث غير النصية.
3. لا تضف مفاتيح تبدأ بـ `mf_` إلى قائمة CPA الأصلية، ولا تستخدم هذا البادئ لمفاتيح أساسية. لا تشغّل مزوّد تحقق حصريًا بالتوازي. المسارات غير المدعومة ليست ضمن ضمان العزل. إذا تعطلت الإضافة أو أُزيلت، مفاتيحها يجب أن تُرفض بواسطة CPA لأنها ليست مفاتيح أصلية.
4. المحاسبة **ليست فاتورة المزوّد ولا سقفًا ماليًا مضمونًا**. التقدير يعتمد بايتات الطلب وحد الإخراج وسعرًا ثابتًا لكل مسار. لا يتعامل بعد مع أسعار cache أو reasoning أو tiers المختلفة. الأسعار يجب أن تغطي أغلى بديل. قد تتجاوز التسوية الحجز فتُمنع الطلبات اللاحقة.
5. يحتفظ النظام بالحجز عند انعدام usage أو فشل غير محسوم أو إعادة تشغيل بعد طلب جارٍ. لا يحرره تلقائيًا لأن المزوّد قد يكون نفّذ الطلب. واجهة مراجعة/تصحيح الحجوزات لم تُبنَ بعد. تكلفة محاولات fallback الفاشلة قد لا تكون معروفة.
6. CPA v7.2.146 يفقد HTTP status في بعض أخطاء host.model. الأخطاء غير المصنفة لا تعاد افتراضيًا؛ خيار `retry_unknown` قد يكرر طلبًا تم تنفيذه أو محاولة بمفتاح مزوّد غير صالح. لا تفعّله دون فهم التكلفة. لا إعادة بعد بث أي محتوى.
7. التخزين الأولي ملف JSON محمي وقفل كاتب واحد؛ كل تغيير يُحفظ ذريًا مع fsync. مناسب للاختبار/الحجم الصغير، **ليس نظام فوترة متعدد العقد**. لا تشغّل نسختين على ملف واحد. لا توجد pagination خلفية أو ضغط سجل بعد.
8. لا توجد حاليًا صفحة مستخدم مستقلة، حدود توكنات دورية، حسابات فرق متعددة الصلاحيات، نسخ احتياطي مشفر من الواجهة، حذف نهائي/إلغاء غير قابل للعودة، واجهة إنجليزية، أو مطابقة تكاليف فعلية لكل مزوّد. هذه متطلبات الإصدار التالي، وليست ميزات مُنجزة.
9. أوقف حركة الطلبات وأعد تشغيل CPA عند تحديث الملف. لا تعتمد على hot reload للإنتاج. اختبارات الضغط، تعطل القرص، إلغاء البث، وتحديث الإضافة أثناء نشاطها تحتاج توسعة.

## البناء والاختبار

المتطلبات: Linux، Go 1.24 أو أحدث، GCC. لا تبعيات Go خارج المكتبة القياسية.

```sh
go test -race ./...
go vet ./...
make build
```

ملف `dist/miftah.so` مرتبط بمكتبة النظام التي بُني عليها. أعد البناء على نظام مطابق لسيرفرك/حاوية CPA؛ بناء glibc ليس لحاوية Alpine/musl.

### اختبار بروكسي محلي حقيقي

ابنِ CPA v7.2.146 من المصدر الرسمي أولًا ثم:

```sh
CPA_TEST_BINARY=/absolute/path/to/cpa-server node tests/integration.mjs
```

ينشئ الاختبار مجلدًا مؤقتًا وCPA محليًا ومزوّدًا وهميًا. يستخدم مفاتيح اختبار فقط. قد يجري CPA نفسه تحديثات قوائم الموديلات العامة؛ الإضافة لا تنشئ اتصالات HTTP مباشرة.

### معاينة الواجهة

```sh
MIFTAH_PREVIEW_TOKEN='choose-a-local-test-token' go run ./cmd/preview
```

افتح `http://127.0.0.1:8741`. هذه معاينة إدارة محلية فقط، ليست بوابة تنفيذ مستقلة ولا تتصل بحساباتك.

اختبار الواجهة يستخدم Playwright كتَبعية تطوير فقط:

```sh
npm ci --ignore-scripts
# شغّل معاينة منفصلة بمفتاح الاختبار المعروف في tests/ui.mjs، وليس في الإنتاج.
npm run test:ui
```

## تثبيت تجريبي معزول

1. انسخ ملف الإضافة إلى مجلد plugins الخاص **بنسخة CPA تجريبية**.
2. اجعل مجلد بياناتها مستمرًا وقابلًا للكتابة من مستخدم CPA فقط؛ في Docker ثبّت المجلد كاملًا كـ volume.
3. الافتراضي أصبح `~/.cli-proxy-api/miftah/state.db` (محتواه JSON). مع حاويتك التي تعمل بحساب root يكون `/root/.cli-proxy-api/miftah/state.db` داخل فوليوم الحسابات الموجود أصلًا؛ لا تحتاج متغير بيئة أو فوليوم بيانات إضافيًا. إذا كان مسار حسابات CPA مخصصًا أو المستخدم مختلفًا، استخدم `MIFTAH_STATE_PATH` صراحة؛ لا يتم اكتشاف auth-dir المخصص تلقائيًا.
4. ادمج `config.example.yaml` في إعدادات النسخة التجريبية دون استبدال إعداداتك أو مفاتيحك.
5. افتح `/v0/resource/plugins/miftah/console` وسجّل بمفتاح إدارة CPA. أنشئ مفتاحًا واختر الموديلات مباشرة. أدخل السعر التقديري للموديلات الجديدة؛ لا يتم افتراض أسعار المزوّد. قائمة الاكتشاف من بيانات حسابات البروكسي وقد تكون غير كاملة؛ الإدخال اليدوي متاح. لا يتم تنزيل ملفات الاعتماد أو إعدادات أسرار المزوّدين.
6. العميل يستخدم نفس عنوان CPA ومفتاحه الافتراضي واسم الموديل الحقيقي، أو اسم مسار اختياري مسموح. ويرسل `max_tokens` أو `max_completion_tokens` أو `max_output_tokens` حسب البروتوكول.

إعدادات السعر والبدائل للموديل المباشر مشتركة بين المفاتيح التي تسمح به، وليست خاصة بمفتاح واحد. السماح بالموديل يجيز بدائله أثناء الفيل باك فقط، ولا يتيح طلب البديل مباشرة إلا إذا أُضيف إلى قائمة المسموح. الأساسي ثابت، حتى أربعة بدائل قابلة للترتيب. المسارات القديمة محفوظة دون تغيير؛ لا يمكن تحويل اسم مسار موجود إلى موديل مباشر أو العكس بصمت. لا تفترض أن الموديل متاح لمجرد إدخاله يدويًا. شروط وأوجه قصور الفيل باك السابقة ما زالت تنطبق.

```json
{"model":"work-assistant","messages":[{"role":"user","content":"Hello"}],"max_tokens":1024}
```

لا تسلّم مفتاح الإدارة أو المفاتيح الأصلية لمستخدم افتراضي. لا تحتاج الإضافة إلى نسخ أسرار حسابات المزوّدين. النسخ الاحتياطي اليدوي: أوقف النسخة التجريبية وانسخ مجلد بياناتها كاملًا إلى مكان آمن؛ لا تحفظه داخل Git.

## الملكية والنشر

الكود الجديد مخصص لصاحب المشروع. المستودع عام بموافقة صاحبه: https://github.com/twuijri/cpa-plugin-miftah . لا يوجد تسجيل في المتجر الرسمي. راجع [دليل التثبيت](INSTALL.md) لإضافة مصدر `registry.json` من الواجهة أو التنزيل اليدوي. يمكن تغيير حقل المستودع عند بناء نسخة مخصصة عبر:

```sh
go build -buildmode=c-shared -ldflags '-X miftah.local/plugin/internal/bridge.Repository=YOUR_ACTUAL_REPOSITORY_URL' -o dist/miftah.so ./cmd/plugin
```

رفع الملف إلى سيرفرك لا يسجله في المتجر العام. يمكن التثبيت المحلي أو إعداد registry خاص؛ إدراج المتجر الرسمي خطوة منفصلة تخضع لإدارة مصدر المتجر. لم يتم نشر أي شيء تلقائيًا.
